Chapter 2A: 基础C语言与Linux

这节 Tutorial 其实没讲多少新的 OS 理论。前半段是把 Lecture 里面的 Process、System Call、Signal 这些东西重新串了一遍，后半段大半时间都在确认一件事：我们至少有足够的 Linux 和 C 语言基础，不至于后面写 OS 代码的时候先被 Pointer 和 Segmentation Fault 送走。

所以真正值得留下来的东西也就三块：几个很容易混的 OS 概念、Linux 下的基本工作流，以及写 Systems Programming 需要的 C 语言基础。

C for Operating Systems

这部分大多数都是 C 语言基础。但 OS 代码和普通 Algorithm 题不太一样：你会大量直接碰 Memory、Pointer、Buffer、Struct 和 System API。所以这里真正需要建立的是一个意识——**这块 Memory 在哪？谁拥有它？这个 Pointer 现在指向什么？这块 Memory 还能活多久？**只要这几个问题开始含糊，Segmentation Fault 一般就在来的路上。

Pointer：本质就是 Address

这里 x 是一个 int，&x 是 x 的地址，p 是保存 x 地址的变量，*p 则是去 p 保存的地址，把里面那个 int 拿出来。假如 x 存在 0x1000，那么 p = 0x1000，*p = 42。

所以 *p = 100; 不是把 p 改成 100，而是顺着 p 找到它指向的 Memory，把那里的内容改成 100，于是最后 x == 100。

Pointer 存在，不代表它指向的东西存在

这个非常重要。int *p; 只代表我声明了一个能够保存 int 地址的 Pointer，它没有顺便给你 Allocate 一个 int，此时 p 甚至可能只是某个 Garbage Address。如果直接 *p = 10;，相当于随便抽一个不知道哪来的地址往里面写 10，那整个晋西北马上乱成一锅粥。

相比之下，int *p = NULL; 至少明确告诉我们 p 目前没有指向一个 Valid Object，所以可以：

但你当然不能 *p = 10;，因为 NULL 仍然不是一个可以 Dereference 的地址。一句话：Declaring a pointer does not allocate memory.

Array 和 Pointer

Array 里面的元素在 Memory 中是连续存放的，所以 a[2] 和 *(a + 2) 拿到的都是 30，也就是 a[i] == *(a + i)。但是不要因此直接把 “Array = Pointer” 写进脑子，它们关系非常近，但不是同一个概念。

Pointer Arithmetic

假设有一个 int *p，那么 p + 1 并不是地址数字单纯加 1 Byte，而是移动到“下一个 int”的地址。所以如果 sizeof(int) = 4、p = 0x1000，那么 p + 1 = 0x1004，p + 2 = 0x1008。Pointer Arithmetic 按照它指向的 Type 作为移动单位。

C String 就是 Character Array

Memory 里面真正放的是：

最后这个 '\0' 叫做 NULL Terminator。所以 strlen("hello") 返回 5，但实际 Storage 需要 6 Bytes，因为 \0 自己也占位置。

很多 C String Function 根本不知道你的 Array 有多长，它们的逻辑差不多就是一直往后读，什么时候看到 '\0' 就认为 String 结束了。所以如果你把 Terminator 搞没了，它就有机会一路读到天涯海角。

常见的 String Operation 有 strlen()、strcmp()、strcpy()、strcat()，而 memcpy()、memset() 更偏 Raw Memory Operation。简单来说，String Function 把 Memory 理解成 '\0' 结尾的字符串，Memory Function 眼里就是一坨 Raw Bytes。

四个基本 API 分别是：malloc() 负责 Allocate，初始内容不保证是什么；calloc() 是 Allocate + Zero Initialize；realloc() 用来 Resize，注意地址可能会变；free() 则负责 Release。特别是 realloc() 并不保证原地扩容，它完全可能把整块 Memory 搬到一个新的 Address。

C 的 Memory 死亡四件套

Uninitialized Pointer

Pointer 里面是未知地址，然后你还 Dereference。

Memory Leak

这块 Memory 已经没有用了，但是你一直没还。

Use After Free

p 这个变量可能还留着原来的地址数字，但是那个 Memory Object 已经死了，这个地址已经不再属于你。

Out of Bounds

合法 Index 只有 0 到 9，10 已经出去了。

这四种错误看起来不同，本质上其实都是一件事情：程序脑子里对 Memory 的理解，和这块 Memory 真实的有效范围 / Lifetime 对不上了。Uninitialized Pointer 是从来就不知道地址是否合法，Use After Free 是以前合法、现在死了，Out of Bounds 则是起点合法、但算出去的地址越界了。
